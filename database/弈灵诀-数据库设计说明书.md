## 1 文档说明

### 1.1 编写目的

本文档描述《弈灵诀》的数据库设计，包含数据库概览、ER 关系、表结构字段说明、完整可执行 SQL 脚本（建表 / 初始化数据 / 重置）、数据一致性校验语句与执行注意事项。可直接作为课程设计文档提交，也可作为开发落地的数据库执行依据。

### 1.2 适用范围

覆盖两类数据：

1. **静态配置数据**：羁绊、羁绊档位、英雄、英雄羁绊关联、卡池配置、等级配置、商店刷新概率、全局参数、管理员账号。由 `seed.sql` 一次性导入，后台可维护。
2. **动态对局数据**：对局、对局内玩家、回合战斗记录、对局存档、幂等记录、后台操作日志。由接口运行时写入。

## 2 数据库概览

### 2.1 基本信息

| 项 | 值 |
| --- | --- |
| 数据库名 | `yi_ling_jue` |
| 字符集 | `utf8mb4` |
| 排序规则 | `utf8mb4_unicode_ci` |

### 2.2 表清单

#### 配置类（9 张）

| 序号 | 表名 | 说明 |
| --- | --- | --- |
| 1 | `admin_user` | 后台管理员账号 |
| 2 | `trait` | 羁绊定义（种族 / 职业） |
| 3 | `trait_level` | 羁绊档位效果（2/4/6 件） |
| 4 | `hero` | 英雄棋子基础属性 |
| 5 | `hero_trait` | 英雄与羁绊多对多关联 |
| 6 | `card_pool_config` | 各费用卡池总量 |
| 7 | `level_config` | 等级配置（人口、升级经验、刷新费用） |
| 8 | `shop_odds_config` | 各等级商店出卡概率 |
| 9 | `game_config` | 全局参数（利息等） |

#### 对局类（6 张）

| 序号 | 表名 | 说明 |
| --- | --- | --- |
| 10 | `match` | 对局主表 |
| 11 | `match_player` | 对局内玩家（1 真人 + 7 AI） |
| 12 | `match_round` | 每回合战斗记录 |
| 13 | `match_snapshot` | 对局存档快照 |
| 14 | `idempotency_record` | 写接口幂等记录 |
| 15 | `admin_log` | 后台操作日志 |

> 本期核心数据规模：羁绊 12 条（6 种族 + 6 职业），羁绊档位 36 条，英雄 24 个，英雄羁绊关联 47 条，卡池配置 5 条，等级 9 条，商店概率 45 条。

### 2.3 设计要点

1. **配置驱动**：全部数值、羁绊效果存于数据库，engine 内核只做计算，不硬编码任何数值。
2. **JSON 存效果**：`trait_level.effect_json` 使用 MySQL `JSON` 类型，engine 直接解析为对象叠加属性。
3. **快照式对局存储**：`match_player` 以 JSON 字段存棋盘、备战席、卡池、商店，单条记录即一个玩家的完整状态，读写简单，适合课设规模。
4. **可复现**：`match.seed` 保存随机种子，同种子下抽卡与战斗结果完全一致，便于回放与排错。
5. **乐观锁**：`match.version` 用于并发冲突检测，冲突返回错误码 3008。
6. **幂等**：`idempotency_record.client_request_id` 唯一约束，保证写接口重复提交不重复扣费。

## 3 ER 关系说明

```
admin_user ──1:N──> admin_log

trait ──1:N──> trait_level
trait ──M:N──> hero   （通过 hero_trait 关联）
hero  ──1:N──> hero_trait

card_pool_config   独立配置表
level_config       独立配置表
shop_odds_config   独立配置表（level + cost 联合唯一）
game_config        独立配置表

match ──1:N──> match_player
match ──1:N──> match_round
match ──1:N──> match_snapshot
match_player 与 match_round 通过 round_no、player_index 逻辑关联
idempotency_record  独立表，仅以 client_request_id 唯一约束
```

**关键关系说明**

- 一个英雄恰好绑定 **2 条** 羁绊记录（1 种族 + 1 职业），例外：`hero_id = 24` 黄泉冥王只绑定种族冥灵，共 **1 条**，因此 `hero_trait` 总记录数为 `23 × 2 + 1 = 47`。
- 一个羁绊有 **3 个** 档位（2/4/6 件），12 个羁绊对应 `trait_level` 共 **36** 条。
- 一局对局固定 **8 名** 玩家（`player_index` 0~7，其中 `is_ai = 1` 共 7 人）。

## 4 表结构详细设计

### 4.1 admin_user（后台管理员）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT | PK, AUTO_INCREMENT | 主键 |
| username | VARCHAR(50) | NOT NULL, UNIQUE | 登录账号 |
| password | VARCHAR(100) | NOT NULL | bcrypt 加密后的密码 |
| status | TINYINT | DEFAULT 1 | 1 启用，0 禁用 |
| create_time | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| update_time | DATETIME | ON UPDATE CURRENT_TIMESTAMP | 更新时间 |

### 4.2 trait（羁绊定义）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT | PK, AUTO_INCREMENT | 主键，1~6 为种族，7~12 为职业 |
| trait_key | VARCHAR(50) | NOT NULL, UNIQUE | 唯一标识，如 `race_human` |
| name | VARCHAR(50) | NOT NULL | 羁绊名称，如「人族」 |
| type | TINYINT | NOT NULL | **1 = 种族，2 = 职业** |
| description | VARCHAR(255) | NULL | 羁绊简介 |
| create_time | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |

> 注意：`type` 使用 TINYINT 存 1/2，不使用 ENUM 字符串，保证与 seed 数据一致。

### 4.3 trait_level（羁绊档位效果）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT | PK, AUTO_INCREMENT | 主键 |
| trait_id | BIGINT | FK → trait.id, ON DELETE CASCADE | 所属羁绊 |
| required_count | INT | NOT NULL | 激活所需上场棋子数量（2/4/6） |
| effect_json | JSON | NOT NULL | 效果配置对象 |
| — | — | UNIQUE(trait_id, required_count) | 同一羁绊同档位唯一 |

### 4.4 hero（英雄棋子）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT | PK, AUTO_INCREMENT | 主键，1~24 |

| name | VARCHAR(50) | NOT NULL | 英雄名称 |
| cost | TINYINT | NOT NULL, CHECK 1~5 | 费用 |
| base_hp | INT | NOT NULL | 一星基础血量 |
| base_attack | INT | NOT NULL | 一星基础攻击力 |
| attack_speed | DECIMAL(3,2) | NOT NULL | 每秒攻击次数 |
| skill_desc | VARCHAR(500) | NULL | 技能描述 |
| enabled | TINYINT | DEFAULT 1 | 1 启用，0 停用 |
| create_time | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| update_time | DATETIME | ON UPDATE CURRENT_TIMESTAMP | 更新时间 |

| 字段 | 类型 | 约束 | 说明 |

### 5.2 schema.sql（建表）

```sql
-- ==========================================
-- schema.sql 弈灵诀 建表脚本 MySQL 8.0
-- 执行顺序：schema.sql → seed.sql
-- ==========================================
DROP DATABASE IF EXISTS `yi_ling_jue`;
CREATE DATABASE `yi_ling_jue`
    DEFAULT CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;
USE `yi_ling_jue`;

-- ---------- 1. 后台管理员 ----------
CREATE TABLE `admin_user` (
    `id`          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
    `username`    VARCHAR(50)  NOT NULL COMMENT '登录账号',
    `password`    VARCHAR(100) NOT NULL COMMENT 'bcrypt加密密码',
    `status`      TINYINT      NOT NULL DEFAULT 1 COMMENT '1启用 0禁用',
    `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_admin_username` (`username`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='后台管理员账号';

-- ---------- 2. 羁绊定义 ----------
CREATE TABLE `trait` (
    `id`          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键 1-6种族 7-12职业',
    `trait_key`   VARCHAR(50)  NOT NULL COMMENT '唯一标识key',
    `name`        VARCHAR(50)  NOT NULL COMMENT '羁绊名称',
    `type`        TINYINT      NOT NULL COMMENT '1=种族 2=职业',
    `description` VARCHAR(255) DEFAULT NULL COMMENT '羁绊简介',
    `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_trait_key` (`trait_key`),
    KEY `idx_trait_type` (`type`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='羁绊定义表';

-- ---------- 3. 羁绊档位效果 ----------
CREATE TABLE `trait_level` (
    `id`             BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键',
    `trait_id`       BIGINT NOT NULL COMMENT '所属羁绊',
    `required_count` INT    NOT NULL COMMENT '激活所需棋子数量',
    `effect_json`    JSON   NOT NULL COMMENT '效果配置对象',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_trait_count` (`trait_id`, `required_count`),
    CONSTRAINT `fk_tl_trait` FOREIGN KEY (`trait_id`) REFERENCES `trait` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='羁绊档位效果表';

-- ---------- 4. 英雄棋子 ----------
CREATE TABLE `hero` (
    `id`           BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
    `hero_key`     VARCHAR(50)  NOT NULL COMMENT '唯一标识key',
    `name`         VARCHAR(50)  NOT NULL COMMENT '英雄名称',
    `cost`         TINYINT      NOT NULL COMMENT '费用1-5',
    `base_hp`      INT          NOT NULL COMMENT '一星基础血量',
    `base_attack`  INT          NOT NULL COMMENT '一星基础攻击力',
    `attack_speed` DECIMAL(3,2) NOT NULL COMMENT '每秒攻击次数',
    `skill_desc`   VARCHAR(500) DEFAULT NULL COMMENT '技能描述',
    `enabled`      TINYINT      NOT NULL DEFAULT 1 COMMENT '1启用 0停用',
    `create_time`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_hero_key` (`hero_key`),
    KEY `idx_hero_cost` (`cost`),
    CONSTRAINT `ck_hero_cost` CHECK (`cost` BETWEEN 1 AND 5)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='英雄棋子表';

-- ---------- 5. 英雄羁绊关联 ----------
CREATE TABLE `hero_trait` (
    `id`       BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键',
    `hero_id`  BIGINT NOT NULL COMMENT '英雄',
    `trait_id` BIGINT NOT NULL COMMENT '羁绊',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_hero_trait` (`hero_id`, `trait_id`),
    KEY `idx_ht_trait` (`trait_id`),
    CONSTRAINT `fk_ht_hero`  FOREIGN KEY (`hero_id`)  REFERENCES `hero` (`id`)  ON DELETE CASCADE,
    CONSTRAINT `fk_ht_trait` FOREIGN KEY (`trait_id`) REFERENCES `trait` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='英雄羁绊关联表';

-- ---------- 6. 卡池配置 ----------
CREATE TABLE `card_pool_config` (
    `id`        BIGINT  NOT NULL AUTO_INCREMENT COMMENT '主键',
    `cost`      TINYINT NOT NULL COMMENT '费用1-5',
    `pool_size` INT     NOT NULL COMMENT '该费用卡池总量',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_pool_cost` (`cost`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='卡池全局配置表';

-- ---------- 7. 等级配置 ----------
CREATE TABLE `level_config` (
    `level`           TINYINT NOT NULL COMMENT '等级1-9',
    `exp_to_next`     INT     NOT NULL COMMENT '升下一级经验',
    `max_board_slots` TINYINT NOT NULL COMMENT '最大上场人口',
    `refresh_cost`    TINYINT NOT NULL COMMENT '刷新商店花费',
    PRIMARY KEY (`level`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='等级配置表';

-- ---------- 8. 商店出卡概率 ----------
CREATE TABLE `shop_odds_config` (
    `id`          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
    `level`       TINYINT      NOT NULL COMMENT '等级1-9',
    `cost`        TINYINT      NOT NULL COMMENT '费用1-5',
    `probability` DECIMAL(6,4) NOT NULL COMMENT '出卡概率 同等级5条之和=1',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_odds_level_cost` (`level`, `cost`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商店出卡概率表';

-- ---------- 9. 全局参数 ----------
CREATE TABLE `game_config` (
    `id`           BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
```

### 6.1 校验语句（导入完成后执行，全部返回空结果即正常）

```sql
-- 1) 英雄总数应为 24
SELECT COUNT(*) AS hero_count FROM `hero`;
-- 期望：24

-- 2) 羁绊总数应为 12，其中种族 6、职业 6
SELECT `type`, COUNT(*) FROM `trait` GROUP BY `type`;
-- 期望：1→6，2→6

-- 3) 每个羁绊必须有 3 个档位
SELECT `trait_id`, COUNT(*) AS lv_count FROM `trait_level`
GROUP BY `trait_id` HAVING lv_count <> 3;
-- 期望：空结果

-- 4) 英雄羁绊关联总数应为 47（23个双羁绊 + 1个单羁绊）
SELECT COUNT(*) AS hero_trait_count FROM `hero_trait`;
-- 期望：47

-- 5) 除黄泉冥王外每个英雄必须恰好 2 条羁绊
SELECT h.id, h.name, COUNT(ht.id) AS t_count
FROM `hero` h LEFT JOIN `hero_trait` ht ON ht.hero_id = h.id
GROUP BY h.id, h.name HAVING t_count <> 2;
-- 期望：仅返回 hero_id=24 黄泉冥王（t_count=1）

-- 6) 每个等级商店概率之和必须等于 1.0000
SELECT `level`, SUM(`probability`) AS total
FROM `shop_odds_config` GROUP BY `level` HAVING total <> 1.0000;
-- 期望：空结果

SELECT c.`cost`, c.`pool_size`,
```

## 7 执行顺序与注意事项

### 7.1 执行顺序

```
①（可选）reset.sql   清空旧表
② schema.sql        建库 + 建表 + 外键索引
③ seed.sql          导入全部初始化数据
④ 6.1 校验语句      验证数据完整性
```

### 7.2 注意事项

| 序号 | 事项 | 说明 |
| --- | --- | --- |
| 1 | `trait.type` 用 TINYINT | 存 1/2，不要改成 ENUM('race','class')，否则 seed 的 1、2 会报错 |
| 2 | 外键导入顺序 | `trait` 必须先于 `trait_level`；`hero`、`trait` 必须先于 `hero_trait` |
| 3 | `hero_trait` 最后一条 | 黄泉冥王写法为 `(24,6);`，语句必须带分号结束 |
| 4 | JSON 字段 | MySQL 8.0 会校验 JSON 合法性，单引号包裹、内部用双引号，不要写成中文引号 |
| 5 | 字符集 | 全库 utf8mb4，中文英雄名才能正常写入与查询 |
| 6 | 重复执行 | seed.sql 未做去重，重复执行会触发唯一键冲突，重导前先跑 reset.sql 或 schema.sql |
| 7 | `battle_max_seconds` | engine 战斗循环的兜底上限，避免极端阵容死循环 |

### 7.3 与 engine 内核的字段约定

**`trait_level.effect_json` 的 key 清单（engine 解析契约，不可随意改名）**

| key | 含义 | 单位 | 消费模块 |
| --- | --- | --- | --- |
| atkPercent | 攻击力提升 | 整数百分数（12 = 12%） | stats.js |
| hpPercent | 最大生命提升 | 整数百分数 | stats.js |
| lowHpDmgPercent | 低于阈值时增伤 | 整数百分数 | combat 层动态 buff |
| hpThreshold | 上述增伤的血量阈值 | 小数（0.5 = 50%） | combat 层动态 buff |
| spellLifesteal | 法术吸血 | 整数百分数 | stats.js |
| skillDmgPercent | 技能伤害提升 | 整数百分数 | stats.js |
| reviveChance | 阵亡复活概率 | 小数（0.30 = 30%） | combat 层动态 buff |
| reviveHpPercent | 复活后血量比例 | 整数百分数 | combat 层动态 buff |
| critRate | 暴击率 | 整数百分数 | stats.js |
| critDmgPercent | 暴击伤害提升 | 整数百分数 | stats.js |
| cdReduce | 技能冷却缩减 | 整数百分数 | stats.js |
| healPercent | 治疗量提升 | 整数百分数 | stats.js |
| summonAtkPercent | 召唤物攻击提升 | 整数百分数 | stats.js |
| summonHpPercent | 召唤物生命提升 | 整数百分数 | stats.js |
| enemyAsSlowPercent | 敌方攻速降低 | 整数百分数 | combat 层 debuff |
| allyAsPercent | 友方攻速提升 | 整数百分数 | stats.js |

> **重要约定**：表中百分比类字段值均为「整数百分数」（如 12 表示 12%），engine 统一在解析时执行 `/100` 换算为小数参与计算；`hpThreshold`、`reviveChance` 本身就是小数，不再换算。此约定必须体现在 `stats.js` 与对应 Jest 用例中，避免出现 12 倍数值错误。

**其它字段约定**

- `hero.attack_speed`：DECIMAL(3,2)，含义为每秒攻击次数，`1.10` 表示每秒 1.1 次。
- `card_pool_config.pool_size`：该费用卡池**总量**，engine 抽卡时按该费用内各英雄均分或按配置拆分，抽到后对应英雄余量 −1。
- `match.seed`：写入时必须非空，engine 的 `rng.js` 以此为种子实例化，保证抽卡与战斗可复现。
- `match.version`：每次写操作 +1，接口层做 CAS 校验，冲突返回 3008。
- `idempotency_record.client_request_id`：与请求头中的幂等 ID 一一对应，命中即直接返回 `result_json`，不再执行业务。

## 8 附录：常用维护 SQL

```sql
-- 查询某英雄的全部羁绊（课设演示用）
SELECT h.`name` AS hero_name, t.`name` AS trait_name,
       CASE t.`type` WHEN 1 THEN '种族' ELSE '职业' END AS trait_type
FROM `hero` h
JOIN `hero_trait` ht ON ht.`hero_id` = h.`id`
JOIN `trait` t       ON t.`id` = ht.`trait_id`
WHERE h.`id` = 15;

-- 查询某羁绊的全部档位效果
SELECT t.`name`, tl.`required_count`, tl.`effect_json`
FROM `trait` t JOIN `trait_level` tl ON tl.`trait_id` = t.`id`
WHERE t.`trait_key` = 'job_swordsman'
ORDER BY tl.`required_count`;

-- 查询各费用英雄清单（后台维护参考）
SELECT `cost`, GROUP_CONCAT(`name` ORDER BY `id` SEPARATOR '、') AS heroes
FROM `hero` GROUP BY `cost` ORDER BY `cost`;

-- 统计某局对局进度
SELECT m.`id`, m.`round`, m.`status`, COUNT(mp.`id`) AS total_players,
       SUM(CASE WHEN mp.`eliminated` = 1 THEN 1 ELSE 0 END) AS eliminated_num
FROM `match` m LEFT JOIN `match_player` mp ON mp.`match_id` = m.`id`
WHERE m.`id` = 1 GROUP BY m.`id`, m.`round`, m.`status`;
```
