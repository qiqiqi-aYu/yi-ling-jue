## 1. 环境要求

| 组件 | 要求 | 说明 |
|---|---|---|
| Node.js | **18 或以上** | `server/package.json` 中 `engines.node >= 18`；本项目使用 CommonJS |

## 2. 数据库导入

### 2.1 重要警告

`database/schema.sql` 开头包含 `DROP DATABASE IF EXISTS yi_ling_jue`，会**删除并重建整个数据库**。  
`database/seed.sql` 会清空并重建配置表及后台管理员初始化数据。  

- 只允许在开发/课设环境中从零重建。
- 执行前确认没有需要保留的对局、存档或账号数据。
- 若数据库已有重要数据，先自行备份，不要直接执行上述脚本。
- `database/reset.sql` 同样会清表，不能作为无风险维护命令使用。

### 2.2 从仓库根目录导入

在项目根目录 `D:/自走棋策略游戏` 下执行：

```bash
mysql -u <数据库用户> -p --default-character-set=utf8mb4 < database/schema.sql
mysql -u <数据库用户> -p --default-character-set=utf8mb4 < database/seed.sql
```

命令会提示输入数据库密码。不要在命令行中用明文写密码，也不要把密码粘贴到文档、提交信息或聊天记录中。

如果当前终端不支持 `<` 输入重定向，可在 MySQL 客户端中执行 `SOURCE`：

```sql
SOURCE D:/自走棋策略游戏/database/schema.sql;
SOURCE D:/自走棋策略游戏/database/seed.sql;
```

### 2.3 导入后数据基线校验

连接 `yi_ling_jue` 后执行：

```sql
SELECT COUNT(*) AS table_count
FROM information_schema.tables
WHERE table_schema = 'yi_ling_jue';

SELECT
  (SELECT COUNT(*) FROM hero)                 AS heroes,
  (SELECT COUNT(*) FROM trait)                AS traits,
  (SELECT COUNT(*) FROM trait_level)          AS tiers,
  (SELECT COUNT(*) FROM hero_trait)           AS hero_trait_rows,
  (SELECT COUNT(*) FROM shop_odds_config)     AS odds_rows,
  (SELECT COUNT(*) FROM card_pool_config)     AS pool_rows,
  (SELECT COUNT(*) FROM game_config)          AS game_config_rows;

SELECT level, SUM(probability) AS total
FROM shop_odds_config
GROUP BY level
HAVING total <> 1.0000;
```

预期结果：

- `table_count = 15`。
- `heroes = 24`。
- `traits = 12`（6 种族 + 6 职业）。
- `tiers = 33`。
- `hero_trait_rows = 47`。
- `odds_rows = 45`（9 级 × 5 费）。
- `pool_rows = 5`。
- `game_config_rows = 23`。
- 最后一条查询**无结果**，表示每级概率和均为 `1.0000`。

完整不变量校验 SQL 见 `docs/01-数据库设计.md`，包括引用完整性、卡池均分和羁绊档位可达性。

## 3. 后端配置说明

### 3.1 创建本地环境文件

在 `server/` 目录中：

```bash
cp .env.example .env
```

Windows PowerShell 可使用：

```powershell
Copy-Item .env.example .env
```

然后按本机 MySQL 与部署环境修改 `.env`。`.env` 已被 `.gitignore` 忽略，不得提交。

### 3.2 环境变量

| 变量 | 示例/默认 | 作用 |
|---|---|---|
| `DB_HOST` | `127.0.0.1` | MySQL 地址 |
| `DB_PORT` | `3306` | MySQL 端口 |
| `DB_USER` | `root` | 数据库用户 |
| `DB_PASSWORD` | 占位符 | 数据库密码；必须由本机填写，本文不记录真实值 |
| `DB_NAME` | `yi_ling_jue` | 数据库名，不要改成其他名称 |
| `DB_POOL_SIZE` | `10` | mysql2 连接池上限 |
| `BALANCE_CACHE_TTL_MS` | `60000` | 配置快照缓存毫秒数 |
| `PORT` | `3000` | Express 监听端口 |
| `JWT_SECRET` | 占位符 | JWT 签名密钥，部署环境必须替换 |
| `JWT_EXPIRES_IN` | `7d` | JWT 有效期 |
| `WX_APPID` | 空 | 预留字段，当前后端未参与登录计算 |
| `WX_SECRET` | 空 | 预留字段，当前后端未参与登录计算 |

说明：

- 服务端启动入口 `server.js` 会先加载 `.env`；仅设置系统环境变量而不创建 `.env` 也可以。
- 数据库代码对部分变量设有本地开发默认值。正式部署必须显式配置数据库密码和 JWT 密钥，不能依赖默认值。
- 当前小程序登录只要求传入非空 `code`，由本地工具函数派生稳定 `openid`；`WX_APPID` / `WX_SECRET` 暂不生效。
- JWT 密钥变更后，此前签发的 token 会失效，需要重新登录。

### 3.3 配置数据与缓存

游戏平衡参数来自 MySQL，而不是写死在 engine 中：

- `trait`、`trait_level`：羁绊和档位效果。
- `hero`、`hero_trait`：英雄与羁绊关联。
- `card_pool_config`、`shop_odds_config`、`level_config`：卡池、商店概率、等级参数。
- `game_config`：经济、战斗、积分、幂等 TTL 等全局参数。

`balance.loader.js` 会：

1. 一次性读取上述配置并转换为驼峰快照。
2. 校验概率和、引用完整性、卡池均分和档位可达性。
3. 生成配置内容指纹 `version`。
4. 在 `BALANCE_CACHE_TTL_MS` 时间内复用缓存，并合并并发加载请求。

修改数据库配置后，等待缓存过期或重启服务即可加载新值。H 组后台配置管理接口尚未完整实现，不能假设存在即时刷新端点。

## 4. 服务启动

### 4.1 安装依赖与启动

在 `server/` 目录下：

```bash
npm ci
npm start
```

开发模式可使用自动重启：

```bash
npm run dev
```

启动成功后终端显示：

```text
弈灵诀后端已启动：http://localhost:<PORT>/api/v1
```

### 4.2 健康检查

```bash
curl http://localhost:3000/health
```

成功响应包含 `"status":"ok"`。若修改了 `PORT`，替换命令中的端口。

### 4.3 关闭服务

在启动服务的终端按 `Ctrl + C`。服务收到 `SIGINT` / `SIGTERM` 后会关闭 HTTP 监听并释放 MySQL 连接池。

## 6. 账号与权限

### 6.1 玩家端

- 登录接口：`POST /api/v1/auth/miniapp/login`。
- 请求体需要一个非空 `code`；当前单机课设实现由该 `code` 派生稳定 `openid`。
- 签发 `role=player` 的 JWT。
- 项目没有 `player` 用户表，不做玩家账号持久化。
- 对局归属采用单机课设取舍，详见 `docs/02-后端接口清单.md` §1.1。

### 6.2 后台管理员

- 管理员账号保存在 `admin_user` 表，由 `seed.sql` 初始化。
- 当前默认用户名为 `admin`，账号状态应为启用。
- **初始密码不在本文档中明文记录**。如需登录，请从受控的项目初始化说明或项目负责人处获取；不要将密码写入代码、文档、日志或命令行历史。
- 登录接口：`POST /api/v1/auth/admin/login`。
- 签发 `role=admin` 的 JWT；密码使用 bcrypt 校验。
- `player` 与 `admin` 共用同一套接口，通过 JWT 角色区分权限；管理类写接口目前尚未全部实现。

### 6.3 管理员密码重置方式

若初始口令不可用，可按以下流程重置，不要在文档或提交中保存新口令：

1. 生成新口令的 bcrypt 哈希（把 `NEW_PASSWORD` 替换为临时值）：

   ```bash
   cd server
   node -e "console.log(require('bcryptjs').hashSync('NEW_PASSWORD', 10))"
   ```

2. 使用生成的哈希更新数据库中对应管理员的 `admin_user.password`。
3. 登录验证后立即清理包含新口令的临时命令记录。
4. 如采用重新导入 `seed.sql` 的方式恢复初始账号，必须先确认可以清除现有全部数据。

## 7. 接口调用约定

- 统一前缀：`/api/v1`。
- 请求头：`Authorization: Bearer <JWT>`。
- 所有写操作必须带 `clientRequestId`（UUID v4），可放在请求体或 `X-Client-Request-Id` 请求头。
- 成功响应的 `code` 为 `0`；失败响应的 `code` 见 `docs/02-后端接口清单.md` §1.3。
- 金币变动接口返回 `goldBefore` / `goldAfter`，便于对账。
- 当前实际挂载的路由以 `server/src/routes/index.js` 为准，共 32 个；26 个 P0 接口已实现，H 组后台管理接口尚未全部实现。

快速连通性验证：

```bash
# 健康检查
curl http://localhost:3000/health

# 玩家登录（code 为本地演示值）
curl -X POST http://localhost:3000/api/v1/auth/miniapp/login \
  -H "Content-Type: application/json" \
  -d '{"code":"local-dev-code"}'

# 管理员登录（请把占位符替换为受控环境中的口令，勿保存到命令历史）
curl -X POST http://localhost:3000/api/v1/auth/admin/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"<从受控来源获取>"}'
```

## 8. 常见问题排查

### 8.1 启动失败：缺少模块

现象：`Cannot find module 'express'`、`mysql2`、`jsonwebtoken` 等。  
处理：在 `server/` 下执行 `npm ci`；若依赖清单有变化再执行 `npm install`。

### 8.2 数据库连接失败

依次检查：

1. MySQL 8.0 服务是否运行。
2. `DB_HOST` / `DB_PORT` 是否正确。
3. `DB_USER` / `DB_PASSWORD` 是否有权限访问 `yi_ling_jue`。
4. `.env` 是否放在 `server/` 目录，而非项目根目录。
5. 数据库是否已按 `schema.sql → seed.sql` 导入。
6. 防火墙或容器网络是否放行 MySQL 端口。

错误中若出现 `Unknown database 'yi_ling_jue'`，说明数据库尚未创建。

### 8.3 配置校验失败（code 4001）

常见原因：

- 某个等级概率和不等于 `1.0000`。
- 英雄或羁绊引用了不存在的 ID。
- 卡池数量不能按同费用英雄数均分。
- 配置了超过英雄数量、永远无法激活的羁绊档位。
- `trait.type` 被改成非 `TINYINT` 语义。

处理：从 `seed.sql` 恢复定稿配置或修正配置表，然后运行 `npm run config:check`。不要通过修改校验器放宽规则。

### 8.4 接口返回 2001 / 2002

- `2001`：缺少 `Authorization: Bearer <JWT>`，或 token 过期/签名密钥变化。重新登录后再试。
- `2002`：当前 token 的角色不匹配。玩家接口需要 `role=player`，后台接口需要 `role=admin`。

### 8.5 写接口返回 1002

缺少 `clientRequestId`。所有 POST / PUT 写操作都要提供唯一的 UUID v4；同一次业务操作重试时复用同一个 ID，不同操作必须换新的 ID。

### 8.6 写接口返回 3008

这是 `match.version` 乐观锁冲突，通常由使用过期状态提交引起。重新拉取对局状态，取得最新 `version` 后再提交；重试时使用新的 `clientRequestId`。

### 8.7 战斗返回但时间轴为空

检查 AI 玩家的棋盘是否正确持久化。此前曾因运行时字段未映射到 DAO 白名单导致 AI 棋盘为空；新增持久化字段时必须同步 DAO 白名单。可运行 `npm test` 的全链路用例确认。

### 8.8 Jest 进程不退出

集成测试应在 `afterAll` 中调用 `closePool()`。不要长期依赖 `--forceExit` 掩盖连接泄漏；若仍挂起，检查是否额外创建了未关闭的数据库连接。

### 8.9 中文乱码

确认：

- 数据库、表和连接均使用 `utf8mb4`。
- 导入脚本时带 `--default-character-set=utf8mb4`。
- 终端能正常显示 UTF-8。

### 8.10 端口已被占用

修改 `server/.env` 的 `PORT`，重启服务，并同步修改所有请求地址与前端 baseURL。

### 8.11 后台管理接口返回 404

H 组后台管理接口尚未全部实现。当前可使用配置读取接口与已实现的 P0 接口；不要据此判定服务未启动。先访问 `/health` 确认服务正常。
